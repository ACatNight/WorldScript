# 品质贴图交付契约

## 推荐目录

```text
quality/
├─ iron/
│  ├─ common.png
│  ├─ fine.png
│  ├─ rare.png
│  ├─ epic.png
│  └─ legendary.png
├─ copper/
├─ shell/
├─ burst.png
├─ reward_glow.png
└─ source/
   └─ quality_atlas.svg
```

项目已有路径时保持现状，不要为了整洁破坏运行时引用。

## 文件要求

- 格式：透明背景 PNG，建议 RGBA。
- 默认尺寸：`128x128`，除非项目配置明确要求其他尺寸。
- 文件名：小写 ASCII，品质固定为 `common/fine/rare/epic/legendary`。
- 可编辑源：几何资产保留 SVG；复杂绘制保留可继续编辑的分层源或生成说明。
- 透明边距：实体像素距离画布边缘至少 4 px。
- 禁止把五档贴图做成同一图形的纯色替换。
- 禁止不同矿物目录出现完全相同的 core 文件。

## 确定性导出

- 固定 SVG 的 `viewBox`、整图像素尺寸和每格尺寸，例如 `768x256`、单格 `128x128`。
- 使用同一个渲染器和固定版本导出整张 atlas，再按整数坐标裁切，禁止逐格手工缩放或截图。
- 输出使用 sRGB，不附带背景色，不进行自动紧边裁切。
- 在源文件旁记录导出命令、渲染器版本和格子映射；更换工具后必须重新做接触表对比。
- 当前环境没有 SVG 渲染器时，可以继续完成设计源，但不得声称 PNG 已可重复构建。

## 必做验收

1. 原尺寸检查：透明通道、边缘、发光截断、脏像素。
2. `56x56` 检查：轮廓、中心焦点、相邻品质可辨识。
3. 灰度检查：品质不能只依赖颜色。
4. 同品质横向检查：铁、铜、晶体和植物必须保留各自身份。
5. 接触表检查：五档从左到右应有稳定增强，而不是中间档比高档更吵。
6. 路径检查：UI YAML 或代码中的纹理引用必须和交付路径一致。

## 接触表

接触表至少包含：

- 每个矿物的一行五档品质。
- 源尺寸预览。
- HUD 尺寸预览。
- 灰度预览。
- 文件名标签。

## 交付报告

报告必须说明：

- 视觉主题和设计依据。
- 每档品质改变了哪些非颜色特征。
- 每种矿物如何保持材质身份。
- 自动校验的错误和警告数量。
- 尚需客户端截图确认的内容，例如缩放、锚点、动画时长和不同背景下的可读性。
