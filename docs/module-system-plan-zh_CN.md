# WorldScript 模块系统规划

> 状态：规划中
>
> 本文只记录后续设计方向，不代表当前版本已经实现。当前不包含模块加载代码，也不改变现有插件行为。

## 目标

WorldScript 主插件未来内置模块加载系统。管理员可以把官方发布的功能模块 JAR 放入指定目录，由 WorldScript 在启动时识别并加载，从而按需扩展插件功能。

模块可以承载区域保护、Web 管理、第三方插件联动等非核心功能。主插件核心继续专注于区域管理、区域发现和 RPG 世界区域编排。

## 已确定的规则

### 仅允许官方模块

- 初版只允许加载 WorldScript 官方发布的模块。
- 非官方、格式不合法或版本不兼容的 JAR 不得加载。
- 模块加载失败时，只停用该模块并记录清晰日志，不应导致主插件整体启动失败。
- 当前不开放第三方模块 API；未来如开放，需要单独制定 API、签名和兼容性规则。

### 模块依赖

- 初版不支持模块之间的强制依赖。
- 每个模块只依赖 WorldScript 主插件提供的模块 API。
- 可以预留依赖字段和版本检查能力，暂不启用模块间依赖关系。

### 独立配置

每个模块拥有自己的目录和配置文件，避免模块之间或模块与主插件核心配置互相污染。

示例：

```text
plugins/WorldScript/modules/protection/
├── WorldScript-Protection.jar
├── config.yml
└── messages.yml
```

模块配置、消息和资源应由模块自己管理。删除或更新模块时，不应要求修改主插件的核心配置文件。

## 目录与发现

建议的模块目录：

```text
plugins/WorldScript/modules/
```

主插件启动时扫描该目录，读取模块描述信息，依次执行格式校验、官方模块校验、WorldScript 版本兼容性检查和模块初始化。

建议的模块描述信息：

```yaml
id: protection
name: WorldScript Protection
version: 1.0.0
main: com.example.worldscript.protection.ProtectionModule
api-version: 1
requires:
  - worldscript
```

`requires` 字段在初版只用于声明主插件依赖；模块之间的依赖暂不支持。

## 生命周期建议

第一阶段只实现启动时加载，修改模块后通过重启服务器生效。暂不实现运行中的热安装、热卸载和热重载，以降低 Bukkit 监听器、任务和资源清理不完整造成的风险。

后续如果确实需要，可以再增加：

- 模块启用/禁用状态
- 模块版本查询
- 模块诊断命令
- 安全的模块停用和资源清理

## 非目标

本规划暂不包含：

- 第三方任意 JAR 的加载
- 模块市场或在线下载
- 模块之间的强制依赖
- 不重启服务器的完整热更新
- 将所有现有功能拆分为模块

## 后续讨论项

实现前仍需确定模块签名或官方身份校验方式、模块配置热重载策略、模块管理命令以及模块 API 的稳定性和版本迁移规则。
