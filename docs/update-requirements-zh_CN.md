# WorldScript 更新需求整理

本文根据用户反馈整理，用于本次版本开发。当前版本已进入开发准备阶段；除“当前版本开发范围”外，其他内容属于后续规划。

## 开发状态

```text
需求状态：已确认
实现状态：0.1.93 已实现并通过构建与回归检查：解锁 Placeholder、区域发现 Title/音效/首次奖励动作、基础进入条件、全局设置入口及聊天编辑器。尚未完成的已确认项包括“区域级条件开关”和 GUI 图标的 Custom Model Data；NBS、发现记录 GUI、保护 Addon 与模块系统仍属后续规划。
```

## 一、已确认的核心需求

### 1. 区域解锁状态 Placeholder

保留并修复本插件的区域解锁状态 Placeholder：

```text
%worldscript_region_unlocked%
```

返回值固定为：

```text
true
false
```

现有 Placeholder 继续保留：

```text
%worldscript_region_name%
%worldscript_parent_name%
%worldscript_region_path%
```

### 2. 区域发现 Title

玩家首次解锁区域时可以显示 Title 和副标题。

- 默认关闭。
- 仅首次发现时触发。
- 支持独立配置标题、副标题和淡入/停留/淡出时间。
- 主编辑器和区域编辑器都必须提供开关。

### 3. 区域发现音效

玩家首次解锁区域时可以播放 Minecraft 原版音效。

- 默认关闭。
- 与 Title 独立开关。
- 支持音量和音调配置。
- 主编辑器和区域编辑器都必须提供开关。

### 4. 首次发现奖励动作

玩家第一次发现区域时，可以执行一组可配置的奖励动作。奖励动作复用 WorldScript 现有的动作/脚本系统，不另设一套脚本语法。

支持的动作方向包括：

- 执行服务器命令
- 给玩家物品
- 修改玩家或区域变量
- 发送消息
- 播放音效
- 执行 Kether 或其他现有脚本动作

要求：

- 仅在第一次发现时执行，重复进入不重复执行。
- 奖励功能可以独立开关。
- 支持多条动作，并按配置顺序执行。
- 单条动作失败不能阻止区域解锁。
- 支持 Placeholder。
- 主编辑器和区域编辑器都提供奖励开关；奖励内容在区域编辑器中编辑。
- 添加动作时由编辑器提示管理员直接在聊天中输入，输入 `cancel` 可取消。

示例：

```yaml
discovery:
  reward:
    enabled: true
    actions:
      - "message: <green>You discovered the mining area!"
      - "command: give %player% diamond 1"
      - "set_variable: mining_discovered=true"
```

### 5. 条件区域

区域可以配置进入条件，包括 Placeholder 条件和权限条件。

示例：

```text
%your_placeholder% >= 10
```

```text
region.enter.mine
```

要求：

- 支持数字比较：`>`、`>=`、`<`、`<=`、`==`、`!=`。
- 支持配置一条或多条规则。
- 多条规则默认使用 `AND`，管理员可以切换为 `OR`。
- 支持配置拒绝进入提示。
- 没有配置条件的区域保持现有行为。
- 条件功能默认关闭。
- 主编辑器和区域编辑器都必须提供总开关/区域开关。
- 添加条件时由编辑器提示管理员直接在聊天中输入表达式，例如 `%your_placeholder% >= 10`，不要求拼接复杂命令。
- 支持输入 `permission: region.enter.mine` 表示权限条件。
- 输入 `cancel` 可取消当前编辑操作。

## 二、编辑器要求

### 主编辑器 `/ws list`（规划扩展）

当前 `/ws list` 是背包式区域列表 GUI。区域图标交互固定为：左键打开 `/ws edit <区域ID>`，右键传送到区域，中键打开全局设置；分页和关闭按钮保持不变：

```text
区域发现 Title       [开启/关闭]
区域发现音效         [开启/关闭]
NBS 发现音乐         [开启/关闭]
区域发现记录 GUI     [开启/关闭]
条件区域功能         [开启/关闭]
```

### 区域编辑器 `/ws edit <区域ID>`

区域编辑器负责单个区域的覆盖设置，例如：

```text
本区域 Title         [开启/关闭]
本区域音效           [开启/关闭]
本区域进入条件       [开启/关闭]
本区域权限要求       [开启/关闭]
不满足条件时传送     [开启/关闭]
```

### 开关优先级

```text
全局关闭                         = 所有区域均不生效
全局开启 + 区域关闭              = 当前区域不生效
全局开启 + 区域开启              = 当前区域生效
```

初版只提供“开启/关闭”两种状态，不增加“继承全局”状态，保持编辑器操作简单。

编辑器点击开关后应立即保存配置，并显示当前状态。YAML 仍然是完整配置来源，编辑器只是可视化修改入口。

### 条件编辑交互

区域编辑器中的“进入条件”页面提供：

- 条件总开关
- 添加条件
- 删除条件
- `AND / OR` 组合方式
- 拒绝提示设置
- 拒绝动作设置

点击“添加条件”后，编辑器在聊天中提示输入完整表达式。插件负责校验格式、保存结果并反馈错误原因。

### 编辑器分组设计

区域编辑器按管理员任务分组，而不是按底层配置字段平铺：

```text
[Basic]        基础信息
[Gameplay]     玩法规则
[Discovery]    区域发现
[Events]       事件与动作
[Variables]    区域变量
[Effects]      粒子与音效
[Advanced]     高级数据
```

分组职责：

- `Basic`：显示名称、父子区域和区域类型。
- `Gameplay`：进入条件、权限、组合方式、拒绝消息和拒绝动作。
- `Discovery`：发现开关、Title、音效、首次奖励和发现记录 GUI。
- `Events`：进入、离开、交互事件及其动作。
- `Variables`：区域变量和继承值。
- `Effects`：粒子、视觉效果和其他氛围设置。
- `Advanced`：边界、优先级、Content ID 和继承设置。

规划上，`/ws list` 负责区域浏览，并可扩展全局设置和插件状态；`/ws edit <区域ID>` 负责单个区域的详细修改。

## 三、后续功能

### 6. NBS 发现音乐

作为可选扩展加入区域发现流程：

- 支持配置 NBS 文件路径。
- 默认关闭。
- 播放失败不能影响区域解锁逻辑。
- 需要明确播放依赖、播放范围以及是否与原版音效同时播放。

### 7. 区域发现记录 GUI

作为可选功能提供已发现区域列表：

- 默认关闭，不强制玩家使用。
- 支持区域名称、描述、父区域和发现状态。
- 后续可增加分页、未发现区域显示和发现时间。
- 支持 Custom Model Data 图标。

### 8. 条件拒绝后的传送

基础行为先支持取消进入。后续增加可配置处理方式：

```text
CANCEL
TELEPORT
CANCEL_AND_TELEPORT
```

传送失败时必须继续阻止玩家进入。

### 9. 官方模块 JAR 系统

WorldScript 未来内置模块加载器：

- 只允许官方模块。
- 模块放在 `plugins/WorldScript/modules/`。
- 每个模块拥有独立目录和配置文件。
- 初版只依赖 WorldScript，不支持模块之间的强制依赖。
- 通过模块 ID 白名单和描述文件进行识别。
- 初版采用重启后加载，不实现热更新。
- 模块加载失败不能导致主插件整体启动失败。

该功能属于长期架构规划，不纳入当前版本强制范围。

## 四、版本排期建议

### 当前版本开发范围

1. 修复 `%worldscript_region_unlocked%`，固定返回 `true/false`。
2. 增加首次发现 Title，支持主标题、副标题和显示时间。
3. 增加首次发现原版音效，支持音效、音量和音调。
4. 增加首次发现奖励动作，优先支持消息、命令和变量动作。
5. 增加 Placeholder/权限进入条件，支持 `AND/OR`。
6. 增加主编辑器和区域编辑器中的对应分组与开关。
7. 保留 `/ws list` 的左键编辑、右键传送、中键全局设置交互。
8. 增加 GUI 图标的 Custom Model Data 配置支持。

### 后续版本

1. NBS 发现音乐。
2. 区域发现记录 GUI。
3. 条件拒绝后的传送。
4. 区域保护官方模块。
5. 模块化 JAR 加载系统。

## 五、验收标准

- 新增功能默认不强制启用。
- 全局开关和区域开关按既定优先级生效。
- Placeholder、Title、音效和条件功能互不破坏现有区域逻辑。
- 配置错误时给出明确提示，不导致主插件崩溃。
- 编辑器修改后配置可以持久化，并可通过 `/ws validate` 检查。

## 六、开发约束

- 新功能默认关闭，不改变未配置服务器的现有行为。
- 首次发现相关动作只在玩家第一次解锁区域时执行一次。
- 条件检查失败时默认执行 `CANCEL`，不实现传送作为本次版本强制功能。
- `/ws list` 区域图标交互不得被移除：左键编辑、右键传送、中键全局设置。
- `/ws edit <区域ID>` 继续使用聊天编辑器，添加条件和奖励动作时直接提示聊天输入，不要求管理员拼接复杂命令。
- 优先复用现有事件、动作、变量和配置服务，避免新增重复脚本系统。
- 配置解析失败、Placeholder 不可用或单条奖励动作失败时，必须记录可读日志并保护主插件生命周期。

## 七、开发前最终确认

以下内容已作为开发默认值，不再阻塞实现：

- 解锁 Placeholder：`%worldscript_region_unlocked%`。
- Placeholder 返回值：`true` 或 `false`。
- 多条件默认组合：`AND`，可切换 `OR`。
- 条件拒绝默认动作：`CANCEL`。
- Title、音效和奖励默认只在首次发现时触发。
- 全局开关关闭时，区域开关不能强制启用功能。
